## Findings by Category

### 1. Security Vulnerabilities

#### H1. nginx Security Headers Stripped from Static Assets (High)

nginx's `add_header` directive does **not** inherit from parent blocks when a child block defines its own `add_header`. The static assets `location` block at `nginx.conf:19-22` defines `add_header Cache-Control`, which silently removes all four security headers (CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy) from JS, CSS, font, and image responses.

```nginx
# nginx.conf:19-22 — this block strips ALL server-level security headers
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
    # ^^^ Security headers from lines 8-11 are NOT inherited here
}
```

**Impact**: The main JS bundle (`index-*.js`) is served without CSP, X-Frame-Options, or X-Content-Type-Options. While the HTML page retains headers via the `location /` fallback, a missing CSP on the JS file weakens the overall security posture.

**Fix**: Repeat all security headers inside the static assets location block, or use the `ngx_headers_more` module's `more_set_headers` which does inherit. The simplest fix:

```nginx
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
    expires 1y;
    add_header Cache-Control "public, immutable" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Content-Security-Policy "default-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; script-src 'self'; img-src 'self' data:; connect-src 'self'" always;
}
```

**Files**: `nginx.conf:19-22`

#### S1. Google Fonts Loaded from External CDN (Low — carried from prior audit)

#### S2. Humor Engine Entropy Lower Than Diceware (Medium)

The humor engine's word pool is significantly smaller than the EFF diceware list (7772 words). The total search space across all 29 templates with their category sizes is approximately **2^25 (~33 million combinations)**. Standard 3-word diceware provides **2^38.7 (~469 billion combinations)** — roughly 8,000x more combinations.

While 25 bits is adequate against online attacks with rate limiting, it's weak against offline brute-force if an attacker knows the user uses this tool. The app doesn't indicate which mode generated the passphrase.

This isn't a bug — it's a design tradeoff (memorability vs entropy). But users should understand the tradeoff.

**Files**: `src/humorEngine.js` (entire file), `src/wordListUtils.js:117-122` (funny mode integration)

**Security strengths (no issues found):**
- `crypto.getRandomValues()` with rejection sampling — correct and unbiased
- Fisher-Yates partial shuffle for word selection — proper implementation
- No hardcoded secrets, no backend, no data transmission
- Wordlist filtering (non-alpha entries, deduplication)
- Clipboard fallback for non-HTTPS contexts
- CSP, X-Frame-Options, X-Content-Type-Options on HTML responses
- Zero npm vulnerabilities

### 2. Bug Fixes & Error Handling

#### M1. `applyRequirements` Pushes Passphrase Past Max Length (Medium)

When requirements toggles are enabled, characters are appended *after* length-constrained generation. A passphrase generated at exactly `maxLength` (e.g., 32 chars) will become 33-34 chars if Number and Special are both enabled.

```javascript
// src/wordListUtils.js:186-193 — adds 1-2 chars after generation
if (requirements.number) {
  result = result + (secureRandomInt(9) + 1);  // +1 char
}
if (requirements.special) {
  result = result + SPECIAL_CHARS[secureRandomInt(SPECIAL_CHARS.length)];  // +1 char
}
```

The `PassphraseDisplay` component will then show "Exceeds maximum" even though generation itself succeeded.

**Fix**: Reduce `maxLength` by the number of characters that requirements will add before calling `getRandomWordsWithinLength`. In `App.jsx:32`:

```javascript
const reqExtra = (requirements.number ? 1 : 0) + (requirements.special ? 1 : 0);
const result = await getRandomWordsWithinLength(minLength, maxLength - reqExtra, 100, { funnyMode: true });
```

**Files**: `src/App.jsx:32-35`, `src/wordListUtils.js:178-195`

#### B1. Notification Banner Lacks Visual Distinction for Error vs Warning (Low)

The notification component applies a `notification--${severity}` class (`notification--error` or `notification--warning`) but the CSS only styles the base `.notification` class with a warning-amber left border. Error notifications look identical to warnings.

**Fix**: Add CSS for `.notification--error`:

```css
.notification--error {
  border-left-color: #ef4444;
}
.notification--error svg {
  stroke: #ef4444;
}
```

**Files**: `src/index.css` (missing rules), `src/components/NotificationBanner.jsx:21`

**Error handling strengths:**
- Fetch failures properly caught and surfaced to user
- Concurrent generation guard (`if (generating) return`)
- Graceful fallback when constraints can't be met (best-effort result)
- ErrorBoundary catches render crashes with refresh prompt
- Auto-dismiss on warnings, persistent display on errors

### 4. Performance & Code Optimisation

#### O1. Duplicate `secureRandomInt` Implementation (Medium)

The `secureRandomInt` function is implemented identically in both `wordListUtils.js:10-23` and `humorEngine.js:168-178`. Any future bug fix or improvement to one must be manually applied to both.

**Fix**: Extract to a shared `src/crypto.js` utility module and import from both files.

**Files**: `src/wordListUtils.js:10-23`, `src/humorEngine.js:168-178`

#### O2. Generation Loop Creates Redundant Arrays (Low)

Each attempt in `getRandomWordsWithinLength` calls `getRandomWords()` which allocates a full indices array (7806 elements) and performs a partial Fisher-Yates shuffle. For 100 max attempts, this creates up to 100 arrays. In practice, most generations succeed within 3-5 attempts, so the real impact is negligible.

A more efficient approach would be to pre-bucket words by length in the cache, then select from appropriate buckets. But given the ~1ms generation time observed in tests, this is only worth pursuing if the wordlist grows significantly.

**Files**: `src/wordListUtils.js:136-172`

#### O3. Humor Engine Brute-Force Template Selection (Low)

`generateFunnyPassphrase` tries up to 200 random template+word combinations hoping to land within length constraints. It could pre-filter templates by minimum/maximum possible length (sum of shortest/longest words in each category) to skip impossible templates entirely.

**Files**: `src/humorEngine.js:185-207`

#### O4. CSS `box-shadow` on Passphrase Panel (Low)

`.passphrase-panel` has `box-shadow: 0 0 30px var(--accent-glow)` which forces a paint layer. Not a problem at current scale but worth noting for future reference — if animations are added to this element, promote it to its own layer with `will-change: transform`.

**Files**: `src/index.css:87`

**Performance strengths:**
- Wordlist fetched once and cached with stats — efficient
- Production bundle is 66KB gzipped — lean for React 19
- Build completes in 97ms — Vite is fast
- No unnecessary re-renders (components are simple, no prop drilling issues)
- `useCallback` used appropriately on event handlers

`Dockerfile:13` uses `npm install` which resolves dependency ranges and can produce different `node_modules/` across builds. `npm ci` uses `package-lock.json` exactly, ensuring reproducible builds.

**Fix**: Change `RUN npm install` to `RUN npm ci` in `Dockerfile:13`.

**Files**: `Dockerfile:13`

### 8. Developer Experience, Process & Tooling

#### D1. No CI/CD Pipeline (Low — carried from prior audit)

No GitHub Actions or equivalent. Tests, builds, and linting are only run manually. Given the Unraid deployment workflow (push → SSH → pull → docker build), a GitHub Action that runs tests + build on push would catch regressions before deployment.

**Files**: Missing `.github/workflows/`

#### D2. No Pre-commit Hooks (Low — carried from prior audit)

No husky/lint-staged configuration. Without an ESLint config (C2), this is academic — but once linting is set up, pre-commit hooks would enforce it.

**Files**: `package.json` (no husky/lint-staged)

#### D3. No Dependency Update Strategy (Low)

No Dependabot or Renovate configuration. Dependencies are updated manually. Given the zero-vulnerability status, this is low priority but would catch future CVEs automatically.

**Files**: Missing `.github/dependabot.yml`

#### D4. Docker Image Not Tagged by Version (Low)

The build command in CLAUDE.md and README uses `docker build -t password-generator .` which always creates a `latest` tag. No version-tagged images means no rollback capability.

**Fix**: Tag images with the package.json version:
```bash
docker build -t password-generator:$(node -p "require('./package.json').version") -t password-generator:latest .
```

**Files**: `Dockerfile`, `CLAUDE.md`, `README.md`

#### D5. No `.env.example` (Low — carried from prior audit)

The app uses no environment variables, but `.gitignore` lists `.env.*` files. A one-line `.env.example` with a comment would clarify this.

### 10. Process Improvements (User Requested)

#### P1. Automate the Deploy Pipeline

Currently: push to GitHub → SSH to Unraid → git pull → docker build → restart container. This could be a single `npm run deploy` script or a GitHub Action with SSH deployment.

#### P2. Add Version-Aware Docker Builds

Tie `package.json` version to Docker image tags. The CHANGELOG is well-maintained — extend this discipline to images.

#### P3. Bundle Analysis

No bundle analysis tooling. At 66KB gzipped this is fine, but `vite-plugin-visualizer` (or `rollup-plugin-visualizer`) would catch future bloat from new dependencies.

#### P4. Consider Feature Flags for Humor Mode

The humor engine is always-on with silent fallback to diceware. A visible toggle would let security-conscious users opt for pure diceware when entropy matters.
